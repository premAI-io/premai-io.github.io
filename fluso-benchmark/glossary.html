Glossary

Terms used across the benchmark site

This glossary keeps the benchmark readable for non-specialists and makes the fairness language explicit when a term matters to the interpretation.

fairness

Benchmark-valid run

A benchmark-valid run is one that finished without invalidating contamination and matched the release rules for case set, scoring profile, connector tier, harness contract, and fixed judge configuration.

This keeps the leaderboard from mixing fair comparisons with broken or partial runs.

fairness

Comparable set

The comparable set is the subset of runs that share the same case universe, scoring profile, connector tier, harness adapter, and evaluation judge. If one of those shifts, the run moves out of the main leaderboard.

Without a comparable set, a leaderboard can look rigorous while quietly comparing different experiments.

diagnostics

Contamination

Contamination covers problems like exhausted provider quota, broken prerequisites, or session corruption that can change the score for reasons unrelated to the model itself.

The site keeps contaminated runs visible in diagnostics so they do not vanish, but they never count toward the headline ranking.

diagnostics

Completion-semantics failure

These failures happen when the model gathers the right information or writes the right artifact, but still stops with an unnecessary follow-up question, an open loop, or an incomplete handoff instead of closing the task cleanly.

This benchmark is about useful knowledge work, so it tracks whether the job was truly completed, not just partially attempted.

diagnostics

Tool-use failure

Tool-use failures include calling the wrong function, failing to execute the tool, or not using the returned result correctly in the final answer.

Knowledge-work agents often succeed or fail based on how faithfully they interact with systems, not just how well they write prose.

dataset

Task family

Task families let readers see where a model is strong or weak by work type instead of collapsing everything into one headline number.

Most real model differences show up in the shape of performance across work types, not only in one average score.

artifacts

Workbook

The workbook is the audit surface behind the benchmark. It records case identity, outcome, root cause, tool usage, token usage, latency, and contamination status for each model-case result.

It gives reviewers a way to inspect the benchmark at case level instead of relying only on a summary page.

dataset

Connector tier

Lower connector tiers stay closer to local harness behavior, while higher tiers rely more on connector-style flows and live prerequisites. The current release keeps a fixed connector tier so model runs stay comparable.

Changing the tier changes the task shape, so it has to stay fixed inside one fair release.
