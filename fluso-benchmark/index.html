Benchmark

What this benchmark is actually testing

The benchmark is designed to measure completed task execution, not just fluent answers.

What the benchmark is really asking

Can the model complete useful knowledge-work tasks end to end, with the right tools, under the same harness rules?

What counts as success

A case passes when the model finishes the requested work, not when it only writes something plausible or stops one step short.

Why the dataset matters

The suite spans 9 task families because useful work is broader than chat quality. Memory, planning, observability, and connector execution all matter.

Insights

Charts from the benchmark

These are the main evidence charts for the release. They are meant to support the written reading of the benchmark, not replace it.

Chart 1

Headline score bars

Start here. This is the clean ranking for the release and answers the basic question: which models completed more tasks under the same benchmark setup?

Chart 2

Category heatmap

This is the most important chart after the leaderboard because it shows model shape. Two models can look close overall while behaving very differently on connectors, memory, or longer multi-step work.

Chart 3

Cost vs pass rate

This chart turns performance into an efficiency question. A small performance gain should be read differently when it comes with a much larger cost profile.

Chart 4

Latency vs tool volume

This helps separate decisive execution from tool thrashing. Some models settle quickly with fewer calls; others spend more of the tool budget before they finish.

Chart 5

Pairwise swing matrix

This chart isolates the cases where outcomes moved most against GLM-5.1. It is useful because real workflow benchmarks are often decided by hard completion edges, not by small wording differences.

Chart 6

Root-cause stacked bars

This chart separates near-miss completion failures from broader behavior misses. It is mainly a reading aid for why models lose cases, not a headline score on its own.
